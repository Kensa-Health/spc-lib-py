# Test/demo data

Weekly synthetic time series, one CSV per SPC scenario. Deterministically
generated by `generate.py` (fixed seeds — regenerate with `python
data/generate.py` if you ever need to tweak one). Each file's docstring in
`generate.py` states exactly what it's meant to demonstrate, and was
verified by actually running the file through `spc.chart()` — not just
eyeballed. All columns: `period` (ISO date, weekly), `value` (float), plus
`org` (facet) on `xmr_two_facets.csv` only.

These are for **integration tests, demos, and examples** — not for the
fine-grained unit tests in `tests/`, which deliberately construct minimal,
precise inputs per assertion. This data is for "load a realistic-shaped
series and check the whole pipeline behaves," or for rendering a chart
that actually looks like something.

| File | Scenario | Recommended options | What it shows |
|---|---|---|---|
| `xmr_stable.csv` | 26 weeks, pure common-cause variation | defaults | A boring, in-control chart — 0 flagged points. The baseline case everything else contrasts against. |
| `xmr_outlier.csv` | 15 weeks, one isolated extreme spike | `screen_outliers="single_pass"` vs `"iterative"` | The two outlier-screening modes give genuinely different `amr`/limits on this file (not just in theory) — the spike's own moving ranges partly survive a single screening pass. |
| `xmr_shift.csv` | 10 weeks stable, then a genuine sustained shift within the baseline's limits | `limit_mode="fixed_n", fix_after_n_points=10` | `seven_point_shift` fires cleanly, `suggest_rebase()` proposes exactly the true shift date. Re-run with the `segment` default (no `fix_after_n_points`) to see the pre-shift period pick up spurious flags instead — the Phase I/II caveat in `core/segments.py`, reproduced. |
| `xmr_trend.csv` | 8 weeks stable, 7-week monotonic rise, 5 weeks stable at the new level | `limit_mode="fixed_n", fix_after_n_points=8` | `seven_point_trend` fires, and only that rule — nothing else contaminates it. |
| `xmr_two_facets.csv` | Two orgs (`north` stable, `south` shifts halfway through) | `facet_field="org", limit_mode="fixed_n", fix_after_n_points=10` | Each facet's limits are computed independently — `north` stays clean while `south` flags, in the same chart. |
| `xmr_rebase.csv` | A real, known process change at 2024-03-25 | `rebase=[date(2024, 3, 25)]` | Compare against calling `spc.chart()` *without* `rebase` set: 23 of 24 points flag (the pooled pre/post calculation is nonsense) vs. 1 of 24 with the rebase applied. The clearest single illustration of why `rebase` exists. |

## Loading

```python
import pandas as pd

df = pd.read_csv("data/xmr_shift.csv", parse_dates=["period"])
```

Note: `parse_dates` gives you a `pandas.Timestamp`-typed column, not
`datetime.date` — that's deliberate, it's the ordinary way to load a CSV,
and `spc.chart()` normalises it internally (see `core/segments.py`'s
`assign_segments()` docstring).
